# 규칙 한 줄 포맷
- {ID} {조건이면} {동사로 끝나는 명령} (이유: 10자 이내, 선택) (예외: 한 구절, 선택)
  예) DS-03 슬라이드 문장을 그대로 읽지 않는다 (청중 이탈)
  예) PR-01 테스트 없는 PR 은 리뷰를 보류한다 (회귀 검증 불가) (예외: 문서만 바뀐 PR)

## ID 체계
- 전역: G-01, G-02 …
- 스킬별: {스킬 약어}-{번호} (DS-01, PR-01)
- 번호는 재사용하지 않는다 (삭제한 규칙 번호는 비워 둔다)

## 이유 (why)
- 한 구절이면 규칙 끝에 (이유: …)
- 그보다 길면 why.md#{ID} 로 옮기고 규칙 줄은 한 줄 유지
- 이유는 지우지 않는다: 모델은 이유를 알아야 경계 사례를 판단한다
- 날짜 · 회차 · 건수 · 사고 번호는 이유가 아니라 경위다 → why.md#{ID} 출처 칸 (규칙 줄에는 지금 지킬 행동과 이유만)
- 대문자 MUST·ALWAYS 로 강조하지 말고 이유로 설득한다

## 예외
- 예외가 있으면 숨기지 않고 (예외: …) 로 적는다. 예외가 없는데 모델이 흔히 예외로 착각하는 경우는 why.md#{ID} 의 경계 칸에 적는다
- 예외가 둘 이상이면 why.md#{ID} 로 옮긴다

## 용어 (HT-22)
- 용어집(glossary.md)의 표준어만 쓴다. 같은 개념을 다른 말로 바꿔 쓰지 않는다
- 확인: `python scripts/inventory.py --terms {파일}`

## 검사 방식 표시
- (lint): 정규식·카운트로 판정 가능 → lint/forbidden.txt
- (judge): LLM 판정 → evals.json
- 트리거(호출 여부) → trigger-eval.json (별도 파일)

## 금지
- "~하면 좋다", "가능하면", "적절히", "필요하면", "알아서" (판정할 수 없다 — triage 의 모호 힌트와 같은 목록)
- 배경 설명 문단
- 검증 방법이 없는 규칙
